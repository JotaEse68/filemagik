# FileMagik PDF Engine — Railway

Independent professional PDF/Office engine for the FileMagik web application. Repository: `JotaEse68/filemagik`. The web UI lives on Vercel; all remote FileMagik compute lives in the Railway project `filemagik-pdf-engine`.

## Services

- `filemagik-pdf-api`: private server-to-server authenticated FastAPI worker; exposed Railway domain is used **only** by the Vercel server proxy.
- `gotenberg`: Gotenberg 9 + LibreOffice on Railway private network at `http://gotenberg.railway.internal:3000`. No public domain.
- `filemagik-quota-ledger`: 450 MB persistent volume mounted at `/data`, storing only pseudonymous HMAC visitor counters and job reservations, never uploaded documents.

## Deployment requirements

- Source GitHub `JotaEse68/filemagik` branch `main`; root directory `/pdf-engine`.
- Dockerfile `pdf-engine/Dockerfile`, health check `/readyz` on port `8000`.
- Railway pre-deploy `python /app/predeploy_smoke.py` tests Gotenberg private HTTP, real DOCX→PDF, optimizer, authenticated PDF→Word/Excel, rejects missing bearer. Deployment must fail if any dependency check fails.
- On startup `start.sh` verifies the Railway volume and then drops privileges to unprivileged UID 10001.
- `PDF_ENGINE_SECRET`: encrypted, server-only, at least 32 characters.
- `GOTENBERG_URL`: `http://gotenberg.railway.internal:3000`.
- `PDF_ENGINE_QUOTA_DB`: `/data/filemagik-quota.sqlite3` (default).
- `MAX_UPLOAD_MIB`: `12` (Vercel proxy is stricter: 3 MiB).

## Limits and antiabuse

Mandatory, persistent quotas:
- `PDF_ENGINE_HOURLY_VISITOR=4`
- `PDF_ENGINE_DAILY_VISITOR=12`
- `PDF_ENGINE_DAILY_GLOBAL=300`
- `PDF_ENGINE_MONTHLY_GLOBAL=4000`
- `PDF_ENGINE_MAX_INFLIGHT=2`

SQLite usage is serialized across workers, and the volume survives restarts. Vercel supplies an HMAC-pseudonymous client identifier, not the visitor's IP address. Turnstile is optional extra protection when configured, and is validated by Vercel; quotas always remain active.

## Endpoints

- `GET /healthz`: API process health
- `GET /readyz`: live Gotenberg private network readiness; returns 503 when unavailable
- `POST /v1/jobs?operation=pdf-to-docx|pdf-to-xlsx|office-to-pdf|optimize-pdf|redact-pdf&quality=lossless|balanced|maximum`
  - Multipart `file` and (for permanent redaction) `regions`.
  - Headers: `Authorization: Bearer ...`, `X-Filemagik-Visitor` (64 hex chars, HMAC generated by Vercel).
  - Responses: true Office ZIP documents or PDF bytes; 401 missing authorization; 403 visitor identity invalid; 413 max size; 422 unsupported data; 429 rate/concurrency limits; 503 dependency unavailable.

## Fidelity contract

PDF→DOCX/XLSX reconstructs **editable** text, tables and supported images, but cannot promise pixel-perfect original layout. Image-only PDFs require searchable OCR first. DOCX/XLSX/PPTX→PDF uses LibreOffice through Gotenberg. Signed or interactive documents are returned untouched by lossless optimization and rejected for lossy recompression. Original content redaction is permanent for supported PDF pages. The visual editor's selectable original text uses region redaction plus new text placement, not direct rewriting of arbitrary PDF content streams.

No documents are stored after conversion. Only standard infrastructure logs and the quota ledger persist.
